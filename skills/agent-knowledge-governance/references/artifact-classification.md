# 产物三级分类：判定树与边界情形

> 回答一个问题：**这个东西该不该进知识库？**
> 分类标准必须写成可机械执行的规则，否则「我觉得重要」就成了标准。

---

## 1. 为什么要分级

多智能体共用一个库时，最大的问题是**垃圾堆积**。一旦智能体把调试日志、
中间 CSV、API 原始响应都塞进去，库的检索质量就崩了 —— 而库一旦不可检索，
就没人愿意查，于是经验彻底不互通。

三级分类把「该不该进」变成一个**有明确判据的判定**，而不是品味问题。

---

## 2. 判定树

```
agent 生成了文件
   │
   ├─ 是临时计算 / 调试输出 / 缓存 / __pycache__ / .DS_Store？
   │      └─► L3 ❌ 不进库，留 /tmp 或项目缓存目录
   │
   ├─ 是 API 原始响应 / 浏览器 profile / 凭据文件？
   │      └─► L3 ❌ 绝对不进（含隐私风险），日志里只记「调用 X，返回状态 Y」
   │
   ├─ 是实验性脚本（未验证）/ 多版本迭代的中间版？
   │      └─► L2 ⚠️ 默认不进；验证通过才升级 L1，否则留 /tmp
   │
   ├─ 是用户可读的成品（非草稿）/ 已交付可复用的结论？
   │      └─► L1 ✅ 必须进 成果/<批次>/
   │
   └─ 是会话中途的中间状态？
          └─► L2 ⚠️ 选择性：写进日志描述，附件放 过程附件/
```

---

## 3. L1 判定细则（满足任一即为 L1）

### 代码层
```
✅ 可运行的脚本（.py / .js / .sh）且无明显 bug
✅ 已发布的版本（v1.0+）的产物
✅ 通过测试的核心模块
```

### 文档层
```
✅ 用户可读的 Markdown 报告（不是草稿）
✅ 已完成的 PPT / Word / PDF
✅ 已上线的博客文章
```

### 资源层
```
✅ 已生成并实际使用的图片 / 视频 / 音频
✅ 已上传的备份 / 压缩包（最终版）
✅ 已发布的构建产物（dist/ 仅保留 release 版）
```

### 知识层
```
✅ 已确认的调研结论（不是初稿）
✅ 已总结的方法论 / 经验教训
✅ 已成型的索引文件
```

**关键**：**单次会话结束的最终输出 = L1**。即使中途失败，已完成的部分也算 L1 的子集，照常归档 —— 不因为「这次没做完」就丢掉已产出的价值。

---

## 4. L3 黑名单（一律不进库）

```
/tmp/ 下任何文件
调试日志（console.log 输出、临时 stdout）
.pyc / __pycache__/
node_modules/
.DS_Store / Thumbs.db
IDE 临时文件（.swp / *~）
.git/objects/... 等 Git 内部文件
构建缓存（dist/ 仅保留 release 版）
大文件（>50MB，如数据集、视频原始素材 —— 除非它本身就是最终交付）
```

---

## 5. 边界情形处理表

| 场景 | 处理 | 理由 |
|---|---|---|
| 多版本迭代 | 只保留最终版进库；旧版靠 git history，或进 `归档与变更/<域>/版本历史/` | 库不是版本控制系统 |
| 数据分析中间结果 | 日志里写「中间结果见附件」，附件放 `过程附件/` | 可追溯但不打眼 |
| API 原始响应 | **绝对不进**；日志只记 API 名称 + 状态码 | 可能含用户数据 |
| 实验性脚本 | 验证通过后升级 L1，否则留 `/tmp` | 未验证代码进库会误导后来人 |
| 会话中途失败 | 已完成部分算 L1 子集，照常归档 | 部分成果仍有复用价值 |
| 第三方代码克隆 | 进 workspace，**不进库**（除非是要发布的项目源码） | 大量文件会污染图谱 |
| 演示/截图素材 | 进 `成果/raw/`（只读层）或 workspace | 原始素材与成品分离 |
| 大体积二进制 | 留 workspace，库里只留路径指针 + 校验值 | 库要保持可 grep、可 diff |

## 6. 归档目录规范

```
<项目>/成果/
├── 2026-11-06_<批次名>/        ← 每个批次一个目录，日期前缀
│   ├── 01_<主产物>.md
│   ├── 02_<附属>.md
│   ├── raw/                     ← 原始素材（只读，闸门第1项保护）
│   └── 实测证据/                ← 原始日志、截图、JSON
└── 00_索引.md / 交付索引.md      ← 批次内的 wikilink 清单
```

**批次命名**：`<YYYY-MM-DD>_<主题>`，用日期前缀保证时间序。

---

## 7. 判定失败的常见借口

| 借口 | 实际情况 |
|---|---|
| 「这个调试日志挺重要的」 | 重要的是**结论**，不是日志。结论进 L1，日志进 raw 或 /tmp |
| 「先放进来，以后可能用」 | 以后不会用。真正会用的会进 L1 |
| 「这是别人的代码，先存着」 | 存 workspace。库是**你的**产出，不是下载仓库 |
| 「删掉可惜」 | git 里有历史。库不是回收站 |
| 「我马上要用了」 | 马上用的在 workspace 里正好——它就在你手边 |
