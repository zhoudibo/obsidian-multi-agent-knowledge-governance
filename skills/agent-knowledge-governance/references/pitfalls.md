# 实战踩坑清单

> 全部来自真实运行 —— 每条都是「症状 → 原因 → 对策」。
> 这是本技能最不能删的部分：规则告诉人「应该怎么做」，坑告诉人「哪里会出事」。

---

## 1. 知识库结构类

### 1.1 同一 vault 里存在两套同名根目录 ⚠️ 高频

**症状**：文件明明写进去了，索引里却找不到；图谱上看不出任何异常。

**原因**：迁移过程中留下了两套同名的根目录（例如
`WorkBuddy智能体日志/` 和 `智能体协作治理/WorkBuddy智能体日志/`）。
Agent 按直觉选了其中一个，而索引在另一个。

**对策**：
- **写入前必查同步协议**，确认权威路径，不要凭记忆
- 在根目录 `AGENTS.md` 里**写死**绝对路径，不要用相对路径
- 目录名带版本或序号（`WorkBuddy智能体日志-v2/`）避免歧义
- 定期审计：`find <vault> -type d -name '*智能体日志*'` 找出重名分支

### 1.2 孤儿节点污染图谱

**症状**：Obsidian 图谱视图出现大量孤立圆点，核心结构被淹没。

**原因**：每次新建文件都只在本地放着，没在已有索引加链接。

**对策**：
- 归档时**必须**在**已有的**项目索引加 wikilink
- **禁止**建独立索引文件（见 `indexing-and-links.md` §1）
- 定期跑 `check_orphans.py`，孤儿数必须恒为 0

### 1.3 批量移动导致断链

**症状**：索引里的链接点开是空白页。

**原因**：`mv` 移动了一批文件，但 wikilink 里的路径前缀没改。

**对策**：
```bash
# 1. 备份 → 2. 移动 → 3. 脚本替换前缀 → 4. 断链扫描 → 5. 孤儿扫描 → 6. 闸门
```
**永远不要用 `for f in $(find ...)`** —— 文件名含空格会丢文件。
用 `while IFS= read -r`。

### 1.4 同主题多张重复卡

**症状**：同一个主题有 3–5 张内容高度重叠的卡，图谱上连成一团。

**原因**：没有「同类合并」原则，每个 agent 各建各的。

**对策**：
- 同一主题/项目 → 合并为 **1 张主卡**
- 合并**不丢信息**：独有内容并入主卡
- 旧版进 `归档与变更/<域>/版本历史/`
- 合并前整批备份，合并后跑断链 + 孤儿扫描

## 2. 多智能体协作类

### 2.1 依赖 subagent 自报告 ⚠️ 高频

**症状**：子代理报告「已归档到 X 路径」，实际文件躺在 `/tmp`。

**原因**：subagent 的返回值是**自述**，不是事实。

**对策**：
```bash
ls -la <预期路径>     # 必须自己验证
# 发现放错 → 立即 mv
```
**规则 5：subagent 输出必须验证。绝不依赖自报告。**

### 2.2 一次性反馈改了全局规则

**症状**：规则集快速膨胀，出现互相矛盾的硬约束。

**原因**：智能体过度服从，听到一次吐槽就改全局规则。

**对策**：走「聚类 → 版本化 → 批准 → 对照」四步。详见 `feedback-loop.md`。

### 2.3 多个 agent 并发写中央索引

**症状**：索引条目丢失、重复、或互相覆盖。

**原因**：多 agent 同时改同一个文件。

**对策**：**单一写者**原则 —— 中央索引只由一个指定 agent 每日聚合，
其他 agent 提交条目到待办区。

### 2.4 「说做好了」没有证据

**症状**：报告说完成，实际只做了 60%，且已宣布结案。

**原因**：把「执行人报告」当成了「独立核验」。

**对策**：五状态分离 + 有效证据三条件。详见 `evidence-and-handoff.md`。

## 3. 工具与环境类

### 3.1 脚本报错：环境问题还是代码缺陷？

**症状**：跑第三方项目测试，某个用例失败。

**关键判别**（这个区分会直接改变结论）：

| 失败类型 | 判据 | 结论 |
|---|---|---|
| **环境缺失** | `No such filter` / `command not found` / `ModuleNotFoundError` | ✅ **可修**，给出确切修复命令 |
| **代码缺陷** | 断言失败 / 逻辑错误 / 输出与预期不符 | ❌ **真问题**，进报告风险项 |

**实战案例**：某 NCM 解密工具 56 项测试挂了 1 项，报
`No such filter: 'drawtext'`。查下来是本机 PATH 里的 ffmpeg 是精简版，
而 `ffmpeg-full` 早就装好了、只是被 PATH 优先级挡住。
→ **不是代码缺陷，是环境债**，修 PATH 后 56/56 全绿。

**顺带收获**：沙箱实测能暴露静态审计永远发现不了的本机环境债。

### 3.2 用正则扫描结构化内容导致损坏 ⚠️ 严重

**症状**：批量修复某类内容后，28 篇文档被改坏。

**原因**：用正则去匹配和替换 HTML/Markdown 的结构，
但正则不理解 DOM 嵌套 —— 匹配边界跨过了元素。

**对策**：
- **结构化修改必须用 DOM 解析**（HTML 用解析器，JSON 用 `json` 模块）
- 正则只用来**定位**（找候选），不用来**修改**
- 批量修改前先在 2–3 个样本上验证

### 3.3 同一首歌/文件被多个工具处理

**症状**：输出目录里文件数比预期少，或有重复。

**原因**：源目录已有同名产物，新工具又转了一遍（或反过来）。

**对策**：转换前先统计源/目标的重叠：
```python
src = {f[:-4] for f in os.listdir(SRC) if f.endswith('.ncm')}
out = {f[:-4] for f in os.listdir(OUT) if f.endswith('.mp3')}
print(f"漏转: {len(src - out)}   多余: {len(out - src)}")
```
**用集合差集量化，而不是靠肉眼数。**

### 3.4 二进制兼容性：最新版可能没有你的架构

**症状**：下载的预编译包在本机跑不起来（`Exec format error`）。

**原因**：release 只发了 arm64，本机是 x86_64 Intel。

**对策**：下载前先确认三件事：
```bash
uname -m                                    # 架构
curl -s https://api.github.com/repos/OWNER/REPO/releases | \
  python3 -c "import json,sys; [print(a['name']) for r in json.load(sys.stdin) for a in r['assets']]"
```
**注意**：最新 release 未必覆盖所有平台，要翻历史版本。

### 3.5 macOS quarantine 阻止执行

**症状**：下载的二进制第一次运行被 Gatekeeper 拦，或行为异常。

**原因**：浏览器下载的文件带 `com.apple.quarantine` 属性。

**对策**：
```bash
xattr -cr <binary>
codesign --force --deep --sign - <binary>   # ad-hoc 签名
```

### 3.6 管道缓冲造成的「假死」

**症状**：`./tool --help | head` 没有任何输出，看起来像二进制坏了。

**原因**：stdout 被管道缓冲，程序还没写完就被 head 关闭了。

**对策**：**直接跑不带管道**。判断二进制是否可用，看 `file` 结果和退出码，
不要靠管道输出判断。

## 4. 内容与交付类

### 4.1 把演示数据当成真实数据

**症状**：文章里的截图是设计稿，数据是编的，读者一核就穿帮。

**对策**：
- 系统界面截图必须是**真实数据**（含真实行数/字段）
- 说明图/架构图/Banner 可以是设计制作
- 明确标注数据源（行数、字段、采集时间）
- 「非演示数据 · 可现场复现」这类标注要能验证

### 4.2 边界情形用「我觉得」判断

**症状**：同一类文件，这次进库下次没进，标准不一致。

**对策**：把判定写成**可机械执行的规则**（见 `artifact-classification.md`），
并用脚本强制。

### 4.3 凭据混进知识库

**症状**：`.env`、`auth.json`、含 token 的日志被归档。

**对策**：
- 归档前必查：`.env` / `auth.json` / `*.key` / `*.pem` / `credentials`
- 质量闸门第 2 项专查敏感内容
- API 原始响应**一律不进库**，只记「调用 X，返回状态 Y」

### 4.4 归档了但没登记索引

**症状**：文件在，索引里没有。

**原因**：以为「文件放对位置就行了」。

**对策**：归档 = **文件移动 + 索引追加 + 日志追加 + ls 验证**，四步缺一不可。
